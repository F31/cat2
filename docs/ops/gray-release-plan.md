# 灰度发布计划（p6 §6.3）

> 目标：小程序审核通过后，按白名单 → 小比例 → 全量分批放量；每批次用同一组指标门槛判定「继续 / 暂停 / 回滚」。
> 回滚优先用特性开关（`sys_feature_flag`）与版本回退；数据库迁移保持向后兼容（先加列/表，后切读写）。

## 批次

| 批次 | 范围 | 最短观察 | 放量方式 |
| --- | --- | --- | --- |
| B0 内测 | 内部员工 + 种子用户白名单 | 1 天 | 特性开关白名单 |
| B1 小比例 | 5% 用户 | 2 天 | 稳定哈希比例 |
| B2 中比例 | 20% 用户 | 2 天 | 稳定哈希比例 |
| B3 大比例 | 50% 用户 | 1 天 | 稳定哈希比例 |
| B4 全量 | 100% | 持续 | 关闭比例限制 |

## 每批次门槛（全部满足才进入下一批）

| 指标 | 门槛 | 来源 |
| --- | --- | --- |
| API 5xx / 错误率 | < 0.5%，且无持续 5 分钟尖峰 | `catcube_http_*` / 网关 |
| feed 首屏 P95 | ≤ 3s | `tests/perf` / 监控 |
| 搜索/详情 P99 | ≤ 1s | 同上 |
| 支付成功率 | ≥ 99.5%，回调失败无持续增长 | `catcube_order_paid_total` / `catcube_pay_notify_failed_total` |
| 注册→画像→匹配→联系→付费漏斗 | 各环节转化不低于上一批次 -20% | `/metrics` + `docs/ops/dashboards.md` |
| Outbox 积压/最老年龄 | 无持续积压；死信=0 | `catcube_outbox_*` |
| 审核 SLA | 超时任务不持续增长 | `review_sla_overdue` / `review_backlog_high` |
| 审计链 | `audit_chain_broken=0` | `catcube_audit_chain_ok` |
| 联系方式抓取 | 无 `contact_scrape_suspected` 突增 | 告警 |
| 履约失败 | 无 `fulfillment_retry_exceeded` 突增 | 告警 |

## 暂停 / 回滚

- **暂停放量**：任一门槛连续 2 个观测窗不达标，或出现 P0/P1 缺陷。
- **立即回滚**：支付/登录/内容安全主链路不可用；资金或审计异常；数据错误扩散。
- 回滚动作：
  1. 关闭对应特性开关（AI/搜索降级等）；
  2. 回退上一版本镜像/小程序版本；
  3. 保留现场（日志/指标/审计），按 `docs/ops/alerts.md` 处置。
- 回滚后必须补一次全量回归与根因记录，再重新从 B0/B1 开始。

## 观测与值守

- 发布窗口：工作日 10:00–17:00；每批次至少 1 名研发 + 1 名运营值守。
- 看板：注册/画像/匹配/联系/付费漏斗、订单与回调、审核积压、Outbox、审计链、履约、AI 成本。
- 每批次结束输出：放量比例、门槛表、异常与处置、是否进入下一批。
