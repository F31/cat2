## 2. D1 详解：后台五角色与权限点（#13）

### 2.1 待决问题（✅ 已于 2026-10-17 确认）

1. **角色集合**：✅ 采用「超管 / 运营 / 审核员 / 财务 / 渠道经理」五角色（矩阵为默认种子，除超管外可配、支持自定义角色）。
2. **后台账号模型**：✅ 一期**复用平台账号 + RBAC**（不新建第二套账号体系）；`sys_admin_user` 预留独立凭证字段，后续可演进。
3. **数据范围**：✅ 非超管角色带 `space_id`；渠道经理默认按区域过滤，**支持多区域 + 含子区域**（`region_codes` + `include_subtree`）。
4. **登录安全**：✅ **连续 3 次登录失败触发短信二次验证**（复用实名手机号）；**IP 白名单由超管后台配置**（未配置=不限制）。
5. **双人复核清单**：✅ 强制「复核 ≠ 执行」的操作清单可由**运营管理员**后台配置（默认：退款/结算打款/会员人工调整/改价格比例/导出）。
6. **敏感操作二次确认**清单：✅ 与上表一致（前端二次确认；服务端审计）。

### 2.3 影响面（若采纳）

- **表**：新增 `sys_admin_user` / `sys_admin_role` / `sys_admin_user_role` / `sys_admin_role_permission` / `sys_admin_login`（`sys_` 内核表）；五角色 + §2.2 矩阵作**默认种子**；角色权限**可配置**；角色数据范围 `space_id` + `region_codes[]` + `include_subtree`。
- **内核**：`policy` 增「复核 ≠ 执行」互斥规则（清单可配）与 **RBAC 反提权/防锁死**（违反 `denied` 记审计）；现存 `requireAdmin` 升级为权限点校验。
- **登录安全**：连续 3 次失败 → 短信二次验证；IP 白名单超管可配；`denied` 审计（防爆破）。
- **契约**：admin.yaml 全量路径标注权限点；`contracts` 登记权限点清单。
- **前端**：admin-web shell 按 RBAC 过滤菜单（菜单级 + action 级）；**角色与权限配置页** + **双人复核清单配置**（运营管理员）；登录失败二次验证交互。
- **测试**：五角色 × 权限点全量表驱动用例（含负向）；`tests/audit` 覆盖面对齐 `p4 §9.4`。
- **工作量**：见 `channel-预研.md` §6，RBAC 单独约 **1.5 人天**，其余 §1–2 约 **3 人天**、§4–8 约 **5.5 人天**。

### 2.4 不拍板的后果

- `channel`（运营商/渠道/佣金/结算）与 RBAC 无法开工；p4 §1–3、§9.1/§9.3、§10.1 持续挂起，p6 §8.1 无法判定完成。
