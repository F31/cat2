# p6-hardening-release · 联调上线

## Why

功能全部就绪后，上线前必须过合规与可靠性硬门槛：PRD 10.4 的容量/性能指标（万级注册、日活千级、峰值并发百级、首屏 ≤3 秒、可用性 ≥99.5%）、安全测试（越权/渗透/支付回放）、S1 部署形态与降级矩阵演练、灰度放量。退出标准是达到 PRD 11.4 验收标准。

## What Changes

- **安全测试**：越权测试（权限矩阵 denied 路径全覆盖）、渗透测试、支付回放测试、依赖漏洞扫描、SAST、联系方式抓取压测与限频告警验证、审计断链告警验证
- **压测**：PRD 10.4.1 目标 + 5~10 倍余量；首屏 ≤3 秒、常规查询 ≤1 秒验证
- **S1 环境**：api×2 + worker×1（含 scheduler）+ 托管 PG 主从 + Redis；健康检查 /healthz /readyz；停机先摘流量再排空任务
- **可靠性与降级演练**：降级矩阵逐项演练（AI→原表单、搜索故障→PG 检索、内容安全超时→审核中队列不放行、Redis→进程内缓存、notice 故障→事件积压重放）；备份恢复演练（RPO≤5 分钟、RTO≤1 小时）；Outbox 积压告警与死信重放演练；履约重试超阈告警 + 手动补偿演练
- **可观测完善**：OTel 全链路、结构化日志带 request_id/module/user_id（脱敏）；业务看板（注册/画像完成度/匹配点击/联系发起/会员转化/支付成功率/猫立方开通/审核积压）；告警初始值（P99>3s、错误率>1%、支付回调失败>0、履约重试超阈、审核 SLA 将超时）
- **灰度发布**：特性开关按用户/比例/白名单放量；小程序体验版→审核→全量，配合服务端开关灰度
- **PRD 11.4 验收**：逐项核对（注册登录一体化、未填手机号不能进入主流程等）

## Impact

- **capabilities**：platform-kernel（运维面：健康检查、降级、灰度开关、告警）、admin-web（死信重放/监控页）
- **代码**：`deploy/`（S1 编排）、`tests/perf`、`tests/security`；各模块降级路径补齐与演练脚本
- **不做**：新功能开发（本阶段只允许缺陷修复与性能/加固类变更）
