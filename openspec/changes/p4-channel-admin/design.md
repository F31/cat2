## 本阶段执行决策

1. **佣金只订阅事件**：channel 订阅 `OrderPaid`/`MemberActivated`，按配置比例 + 比例快照生成 `chn_commission` 流水；计佣范围（首单/续费、是否含立方订阅）以 p0 待确认 #16 结论为准，落到配置而非代码。
2. **「复核≠执行」机制化**：操作级权限点拆分 review/execute 两类，内核 policy 规则强制同一结算单/退款单的操作人≠复核人；违反即 denied 并记审计。
3. **治理分区零业务逻辑**：governance/ 只做聚合与编排（用户 360、代操作入口），写操作仍调目标模块的 admin 契约，审计与事务归属目标模块。
4. **审计点 CI 强制**：模块声明 `AuditPoint{action,级别,记失败否}`；CI 校验声明了 action 的 handler 必须接审计装饰器，出现敏感动词未声明直接失败。
5. **埋点最小化**：一期仅采集漏斗必需 8 事件（register/profile_complete/feed_click/search/detail_view/contact_initiate/member_quote/order_paid），独立 `tlm_` 前缀，与业务数据分离存储；不做过度采集（PRD 1.2.3）。
6. **verify 审核路由**：`reviewer_type`（平台/企业/组织）决定任务进哪个队列；组织认证未通过的组织不能审核成员核验（denied 记审计）。
